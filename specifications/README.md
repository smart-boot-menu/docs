# Smart Boot Menu — Shared Interface Specifications (`v1`)

**Status:** Draft v1.0.0-alpha (Foundational Baseline, 2026-11-26)  
**Canonical Specification Owner:** `smart-boot-menu/docs/specifications/`  
**Canonical Rust & JSON Schema Implementation:** `smart-boot-menu/sbm-common`

> **Single Source of Truth Rule:** No downstream repository (`sbm-uefi`, `sbm-core`, `sbm-as`, `sbm-server`, `sbm-agent`, `sbm-catalog`, `install`, `sbm-lab`) may redefine or copy these wire formats or schemas. All Rust consumers depend on `sbm-common` crates; non-Rust consumers (e.g., SvelteKit frontend, catalog validators) consume the JSON Schemas generated by `sbm-common/schemas/`.

## Versioning & Interface Change Process

1. **Semantic Versioning (`schema_version`):** Every serialized document and wire message carries an explicit `schema_version` (`"1.0"` or `ProtocolVersion { major: 1, minor: 0 }`).
2. **Additive changes (minor bump, e.g. `1.0` -> `1.1`):** New optional fields with sensible defaults; older readers ignore unknown fields unless `must_understand` is set.
3. **Breaking changes (major bump, e.g. `1.x` -> `2.0`):** Require:
   - An RFC/ADR PR in `smart-boot-menu/docs`,
   - Updated Rust types, JSON schemas, and golden test vectors in `smart-boot-menu/sbm-common`,
   - Compatibility negotiation support for the prior major version during deprecation windows,
   - End-to-end validation in `smart-boot-menu/sbm-lab`.
